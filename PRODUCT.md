# Drone Simulator v2

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Students learning visual programming on school laptops, Chromebooks and landscape iPads. Teachers need a fast select, demonstrate, run, reset loop. Exact student ages are unspecified.

## Product Purpose

An interactive rescue drone coding simulator: students build a Flight Program, see a drone execute it in a 3D world, observe mission outcomes, revise and retry.

## Capabilities and Constraints

Preserve working Three.js movement, collision, mission scoring and state, Blockly execution, XML import/export, per-context local persistence and useful assets. Remain a static GitHub Pages-compatible site. No framework migration, save-format change, mission-rule change or physics change without a separate proposal. LOCAL_GIT_ONLY: no remote, push, PR or deployment.

## Operating Context

Desktop, Chromebook/laptop and landscape iPad are first-class. Portrait phones may offer an orientation prompt. First-time students must start without reading a manual. Mission selection → concise briefing → program → run → observe → result → revise/retry.

## Brand Commitments

Modern Rescue Simulation × STEM Learning. Clear, confident, approachable, slightly playful, professional for teachers and engaging for students. Traditional Chinese readability first. Avoid military, hacker, corporate dashboard, neon, decorative gradients, emoji UI and childish cartoon treatments. The earlier SpaceX-inspired design is superseded by the explicit v2 redesign brief.

## Evidence on Hand

Two existing missions, a free practice scene, procedural medical drone, local Kenney assets, mission preview images and existing hero videos. Existing asset provenance is incomplete outside the documented Kenney sources; do not invent licences. See CONTEXT.md for established domain vocabulary.

## Product Principles

- The 3D world is the focal point.
- Make the link between the active block, drone action and mission outcome visible.
- Show information when it helps the current learning task.
- Preserve the functional foundation while replacing the product experience.
- Verify real interactions and rendered screens, not just passing builds.

## Accessibility & Inclusion

Visible keyboard focus, semantic controls, colour-independent status, readable Traditional Chinese, reduced motion, practical Blockly keyboard support, touch targets and modal focus management.
