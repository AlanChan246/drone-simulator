# Mission 3：失控機械工廠

高小與初中學生的 Scratch 概念練習。讀取零件狀態、條件分支、等待機器、重複處理是本任務的重點。主要建築和機器均為 Kenney CC0 模型；沒有新增後端或帳戶。

## 本機開啟

在專案根目錄執行 `npm start`，開啟 http://localhost:8080，進入任務模式，選「失控機械工廠」。首次開啟要成功載入模型。不要以 file:// 雙擊 HTML。

「換一張訂單」位於場景視窗右上角，結算亦保留同一操作。航線、訂單資料及分層提示集中在「任務說明」，不再另佔工作區一行。

第三張任務卡、任務簡報、並排／編程／觀察模式、相機、積木匯入匯出、暫停、單步與結算沿用現有工作區。此任務使用 factory 場景與 `drone-simulator:v1:blockly-workspace:mission-3-factory` 儲存鍵，不讀取舊天空城存檔。

## 教師使用

1. 讓學生先處理一件零件，觀察夾具狀態。
2. 加入「如果 … 那麼／否則」，正常零件直接交付；故障零件放入維修站、啟動、等待完成後取回。
3. 處理一件成功後，整理成重複六次，或重複直到交付數等於六。
4. 保留程式，換訂單測試。固定寫死零件次序只能解特定訂單。
5. 進階學生可把單件流程整理成無參數、無回傳的函式積木，使用數值或文字變數。

教師參考程式：`test/fixtures/factory-reference.xml`。函式版：`test/fixtures/factory-functions.xml`。透過工作區「匯入」載入，再按「執行」。程式不會預載入學生工作區。`node scripts/factory-fixtures.cjs` 可重建這兩個教材檔。

參考航線保持航向0°，使用相對距離與左右平移，飛行高度94cm：起點先向北1500、向東1200、向南1050到取件台。A向北1050到中央路口；西1200到B，東1200到C。交付後回中央路口再南1050到A。六件後由A北1950到出貨平台降落。單位均為cm。這是可量度的清空航線，其他航線仍需要檢查障礙。

## 規則與回饋

30×30m，20×20個150cm單位格。起點(-1200,1200)、A(0,750)、B(-1200,-300)、C(1200,-300)、出貨(0,-1200)，北方為負Z。操作點容許水平100cm內、高度50–180cm；上限高度500cm。一次只夾一件。維修站拒收正常零件，裝配站拒收故障零件。維修有空閒、待啟動、維修中、可取回四態；機器啟動後按模擬時間運作。

每件交付100分，全部完成、夾具清空、飛行後於出貨平台降落200分，共800分。沒有時間、電量、錯誤次數或積木數扣分。正確的六次複製程式仍可完成；結算提示嘗試迴圈。學習回饋依據實際執行的分支及不同迴圈輪次內的交付紀錄。

首次訂單為正常、故障、正常、故障、故障、正常。重設保留程式與該張訂單。換訂單以遞增seed產生另一排列，仍為三正常／三故障，維修時間為6、9、12個模擬秒；資料不會因重讀感測器而變動。訂單seed只在本次場景生命週期內保留，重新進入任務回到首次訂單；Blockly程式持續儲存。

錯誤會停止該次程式並保留現場；先閱讀指出的相關積木，再修改及重設。停止會懸停保留現場；已啟動的機器可繼續工作。暫停在下一塊積木前生效，已開始的等待可以先完成；單步放行下一塊。重設、換訂單、離開場景都會取消舊執行。

交付兩件啟動輸送設備、四件啟動裝配機和工作顯示燈、六件啟動救援能源核心。動畫與實際交付數共用同一狀態來源。

## Scratch 對照

核對來源：[Scratch 官方繁體中文翻譯](https://github.com/scratchfoundation/scratch-l10n/blob/9b0d38b9b9c8220cfad61ad7e3fc29f1d0d001c5/editor/blocks/zh-tw.json)。版本與檔案SHA-256記於 `audit/factory/scratch-source.json`。

| 本任務文字／分類 | Scratch 對照與界線 |
|---|---|
| 控制：重複…次、重複直到… | 官方 CONTROL_REPEAT / CONTROL_REPEATUNTIL；每輪即時讀取結束條件 |
| 控制：如果…那麼／否則 | 官方 CONTROL_IF / CONTROL_ELSE；在執行時讀條件 |
| 控制：等待…秒、等待直到… | 官方 CONTROL_WAIT / CONTROL_WAITUNTIL；與機器共用模擬時間 |
| 變數…設為…、變數…改變… | 官方 DATA_SETVARIABLETO / DATA_CHANGEVARIABLEBY；數值及文字 |
| 運算、偵測、函式積木 | 共通編程概念；保留Blockly的積木形狀及既有運算UI，並非完整Scratch VM |
| 工廠擴充：夾取零件、放下零件、啟動維修 | 本模擬器專用，非Scratch原生 |
| 工廠偵測：取件台有零件？、夾具上的零件狀態、維修完成？、已交付零件數 | 本模擬器專用；狀態為正常／故障／無零件 |
| 飛行指令 | 沿用本模擬器，非Scratch原生；Mission 3禁止絕對座標捷徑，包括匯入 |

不支援參數、回傳值或其他匯入積木時，Run前明確指出。沒有新增 `.sb3` 匯入。等待直到60個模擬秒仍未成立會給除錯診斷，並非遊戲倒數失敗。

## 維護與驗證

`js/factory` 分開管理config、素材、場景、規則、Blockly定義、非同步解譯器、整合及UI。Mission 1、2繼續使用原有指令佇列。解譯器先驗證並凍結積木快照；感測器、變數、分支和迴圈在執行時讀取。沒有eval，具1000輪迴圈、10000步及16層函式上限。碰撞沿整段飛行檢查，不會因長距離積木穿牆。

`npm test`：規則、真正Blockly XML、即時解譯、20種排列、錯誤、迴圈與舊合約。

`node scripts/verify-factory-browser.cjs`：本機伺服器啟動後，以Chrome及 `promo/node_modules/playwright` 執行真實匯入、Run、相對飛行、交付與降落；另檢查新訂單、停止、暫停、單步、錯誤與舊任務。虛擬時鐘只推進真實計時器／動畫回呼，沒有瞬移或修改完成狀態。

`node scripts/verify-static-site.cjs`：在暫存目錄檢查現有靜態網站打包及Service Worker清單，不部署。

素材及修改記錄見 `docs/assets/factory-assets.md`。測試證據、實際效能與限制見 `audit/factory/README.md`。

日常驗證每次輸出至獨立的 `test-results/` 子目錄，不覆寫歷史 audit 或正式預覽圖。共用素材清單、場景生命週期、執行取消與驗證方式見[架構與日常維護](../architecture.md)。
